# منصة مدرسة التناغة الشرقية — Secure Architecture

تمت إعادة هيكلة المشروع إلى Frontend مبني بـ Vite وTypeScript مع Firebase Authentication وFirestore وStorage. الواجهة لا تحتوي على كلمات مرور أو Firebase Admin SDK أو Admin Secrets أو Tokens أو API secrets.

## البنية

```text
src/
  auth/                 Firebase Authentication فقط
  components/           مكونات واجهة صغيرة
  config/               قراءة إعدادات Web العامة من import.meta.env
  database/             خدمات Firestore
  firebase/             تهيئة Firebase Client SDK
  pages/                صفحات الدخول ولوحات الأدوار
  security/             قراءة الدور والتحقق من الصلاحيات
  utils/                التحقق من المدخلات
public/                 HTML والأصول العامة فقط
firebase/
  firestore.rules       صلاحيات Firestore الحقيقية
  storage.rules         صلاحيات رفع PDF
functions/src/           Admin SDK على الخادم فقط لتعيين Custom Claims
```

## إعداد محلي

```bash
cp .env.example .env.local
# ضع Firebase Web configuration العامة في .env.local
npm install
npm run dev
```

إعدادات Firebase Web مثل `apiKey` و`projectId` ليست Admin secrets، لكن لا تضع في `.env.local` أي service-account JSON أو private key أو Admin token. هذه القيم تبقى في بيئة الخادم فقط.

## إعداد Firebase

1. فعّل Email/Password من Firebase Authentication.
2. أنشئ Firestore وStorage.
3. انشر القواعد:

```bash
firebase deploy --only firestore:rules,storage
```

4. ثبّت واعمل وظائف الخادم من مجلد `functions`:

```bash
cd functions
npm install
npm run build
firebase deploy --only functions
```

5. تعيين الدور يتم بواسطة وظيفة `setUserRole` وبصلاحية مدير فقط. المستخدم لا يستطيع تغيير دوره من المتصفح.

## النشر على GitHub Pages

سير العمل `.github/workflows/deploy-pages.yml` يبني `dist` وينشره تلقائيًا مع كل `push` إلى `main`. أضف قيم Firebase Web العامة كـ **Repository Variables** بالأسماء الموجودة في الملف. لا تستخدم GitHub Secrets للـ Admin SDK داخل عملية بناء الواجهة، ولا تمرّر service-account JSON إلى Vite.

فعّل **Settings → Pages → GitHub Actions** مرة واحدة. تم ضبط Vite على `base: './'` حتى يعمل داخل رابط المشروع الفرعي مثل `/El_tanagha_school/`.

## ما الذي بقي ظاهرًا عمدًا؟

- كود الواجهة وملفات JavaScript/CSS: بطبيعتها تُرسل للمتصفح.
- Firebase Web configuration العامة: مطلوبة لتحديد مشروع Firebase وليست وسيلة دخول إدارية.
- أسماء المجموعات والصفحات والأدوار: ليست أسرارًا.

## ما الذي تم نقله خارج الواجهة؟

- كلمات المرور: لا تدخل Firestore ولا `localStorage`؛ Firebase Authentication يديرها.
- تعيين الأدوار: Firebase Custom Claims عبر Cloud Function على الخادم.
- Admin SDK وعمليات الإدارة: داخل `functions/` فقط، ولا يتم استيرادها من `src/`.
- حماية البيانات: داخل Firestore/Storage Security Rules، وليس بإخفاء الأزرار فقط.
- لا يوجد أي اعتماد على `localStorage` لتسجيل الدخول أو حفظ كلمات المرور.
- القراءات تستخدم Firestore Lite وطلبات محدودة؛ SDK الكامل يُحمّل فقط عند عمليات الكتابة.

## قرارات الأداء والاستقرار

- الحزمة الأولى لا تحتوي على Firebase Auth/Firestore الكامل؛ يتم تحميل الخدمات عبر `dynamic import` عند الحاجة.
- لوحة التحكم ترسم shell صغيرًا، ثم تحمّل القسم المطلوب فقط، مع `AbortController` لإلغاء الطلب السابق.
- قراءات Firestore تستخدم `limit(20)` و`startAfter` وcache قصير 30 ثانية، ولا تستخدم realtime listeners بلا حاجة.
- التنقل داخل اللوحة يعتمد على event delegation ومستمع واحد قابل للإلغاء.
- الصور غير الحرجة تستخدم `loading="lazy"`، والوضع الداكن يغير متغيرات CSS بدل إعادة بناء DOM.

## وحدات الميزات

تعريفات ميزات الطالب والمدرس وولي الأمر والمدير موجودة في `src/features/catalog.ts`، بينما التنفيذ العام للنماذج والقوائم والرفع والتصدير موجود في `src/pages/feature.page.ts`. بذلك لا يوجد أربعة نسخ من نفس النموذج، وتُحمّل وحدة الميزات فقط عند فتح القسم.

## لوحات الأدوار الأربع

لوحة التحكم الأساسية موجودة في `src/pages/dashboard.page.ts` وتعرض أربع تجارب مستقلة بصريًا. اللوحة الرئيسية لا تعرض أعدادًا أو أسماء طلاب أو نشاطًا تجريبيًا على أنه بيانات حقيقية؛ تُظهر حالات إعداد وفراغ واضحة إلى أن تُربط المؤشرات بمصادر موثوقة:

- **الطالب:** مساحة تعلم بألوان بنفسجية ومركز التعلّم الذكي.
- **المدرس:** مساحة لإدارة الفصول مع حالات فارغة وإجراءات سريعة للملفات وفيديو YouTube والتقييمات.
- **ولي الأمر:** بوابة متابعة أسرية تُبيّن بوضوح عند عدم ربط حساب طالب.
- **المدير:** غرفة تحكم تعرض شرطات/حالات فارغة بدل أرقام تشغيل غير متصلة بمصدر بيانات.

لكل دور layout وألوان مختلفة. على الشاشات الصغيرة تتحول روابط الأقسام إلى شريط تمرير أفقي قابل للمس، وتحترم الحركة تفضيل تقليل الحركة، مع مؤشر تركيز واضح للتنقل بلوحة المفاتيح. يستخدم التنقل Event Delegation ومستمعًا قابلًا للإلغاء. فتح أي قسم ينشئ طبقة الميزات عند الطلب ولا يحمّل بيانات الأقسام مسبقًا.

## مساحة التعلّم الذكي للطالب

تُحمّل `src/features/student-smart.ts` عند فتح لوحة الطالب فقط. تعرض متابعة آخر درس، توصيات من الدروس والفيديوهات المنشورة، التقويم، الاختبارات والواجبات القادمة، مؤقت مذاكرة، أهداف اليوم والأسبوع، إحصاءات وإنجازات، ملاحظات، محفوظات، بحثًا شاملًا، مركز إشعارات، لوحة أوامر، وسجل النشاط والعناصر المفتوحة مؤخرًا.

المواعيد والمحتوى التعليمي تُقرأ من Firestore عبر خدمات القراءة الحالية وبصفحات محدودة. الأهداف والملاحظات والمؤقت والمحفوظات وسجل النشاط تُخزّن محليًا في المتصفح بمفتاح خاص بمعرّف الحساب، ولا تُزامن بين الأجهزة ولا تُرسل إلى المدرسة. مركز الإشعارات داخل التطبيق فقط؛ لا تُرسل إشعارات دفع.

## فحوصات قبل النشر

```bash
npm audit --omit=dev
npm run build
npm run check
cd functions && npm audit --omit=dev && npm run build
```

تم تحديث `firebase-admin` و`firebase-functions` إلى الإصدارات الحديثة وإضافة override آمن لـ `@grpc/grpc-js` في الواجهة. آخر فحص للاعتماديات أعاد `0 vulnerabilities` للواجهة ووظائف الخادم.


## إدارة فيديوهات YouTube والملفات التعليمية

تُحمّل وحدة `src/features/content-manager.ts` عند فتح أقسام الفيديوهات وملفات الدروس وإدارة المحتوى. يضيف المدرس الفيديو بلصق رابط YouTube فقط؛ تتحقق الواجهة من الرابط، وتستخدم YouTube IFrame Player API لاستخراج العنوان والمدة، وتعرض الصورة المصغرة من YouTube. تُحفظ بيانات الفيديو ورابطه ومعرّفه في Firestore فقط، وتُشغّل المشاهدة داخل نافذة تضمين في الموقع باستخدام مشغّل YouTube؛ لا تُرفع ملفات الفيديو إلى Firebase Storage.

رفع الملفات التعليمية متاح للمدرس والمدير فقط، لصيغ PDF والصور ومستندات Word وعروض PowerPoint حتى 25MB. تحفظ الملفات في Storage ضمن `lessons/`، ثم تسجل بيانات العنوان والمادة ونوع الملف ورابطه ومساره في Firestore. تتضمن المكتبة تصفية حسب المادة، ومعاينة مدمجة للصور وPDF، وزر تنزيل؛ وتُفتح صيغ المستندات والعروض عبر رابط الملف لأن عرضها يعتمد على دعم المتصفح. تطبق قواعد Storage تحقق الدور والحجم ونوع المحتوى على الخادم أيضًا، فلا يعتمد الحظر على عناصر الواجهة وحدها.

استخراج ميتاداتا YouTube يتطلب أن يكون الفيديو عامًا وقابلًا للتضمين، وأن تكون خدمة YouTube متاحة للمتصفح. إذا منع صاحب الفيديو التضمين أو كانت بياناته غير متاحة، لن تسمح الواجهة بحفظه قبل نجاح استخراج العنوان والمدة.

## مراجعة الجودة والأمان

- تم تشديد قواعد Firestore لعزل التقارير والإشعارات والرسائل، ومنع الطالب من تعديل أو حذف التسليم بعد إنشائه، وفصل صلاحيات قراءة وكتابة المحفوظات.
- تم ربط رفع/حذف الملفات بمجلد المدرس، مع صلاحية المدير؛ كما تحاول الواجهة حذف الملف المرفوع إن فشل حفظ بياناته الوصفية.
- تُظهر مكتبة المحتوى خطأ التحميل وإمكانية إعادة المحاولة بدل عرض قائمة فارغة توحي بعدم وجود محتوى.
- قواعد `firebase/firestore.rules` و`firebase/storage.rules` **مصدر إعداد فقط ولم تُنشر إلى مشروع Firebase حي**. يلزم مراجعتها مع مخططات المشروع الفعلية، ثم نشرها واختبارها في بيئة staging قبل الاعتماد الإنتاجي.
- معاينة الصور وPDF داخل المنصة؛ أما ملفات Word وPowerPoint فتُفتح كرابط تنزيل/ملف وتعتمد معاينتها على المتصفح، ولا يوجد عارض Office مدمج.
- لا يوجد في المشروع حاليًا إطار اختبارات واجهة تلقائية أو بيانات staging موثقة؛ التحقق المتاح هو فحص TypeScript والبناء، ولا يعد بديلًا عن اختبارات صلاحيات Firebase الفعلية.

## الصفحة العامة وتحسينات لوحات الأدوار

تبدأ المنصة الآن بصفحة عامة متجاوبة بهوية مدرسة التناغة الشرقية، تستخدم صورة المدرسة وشعارها، وتعرض مسارات الطالب والمدرس وولي الأمر والإدارة قبل الانتقال إلى تسجيل الدخول الآمن. يتوفر رابط رجوع من نموذج الدخول، وتعمل دعوة الدخول على عرض متطلبات Firebase بدل تعطيل الصفحة العامة إذا لم تُضبط البيئة.

تحتفظ كل لوحة بهويتها المستقلة وألوانها وترتيبها، مع رموز تنقل مختلفة، ويعرض الطالب تحية حسب الوقت واسمه، وتقدمًا مشتقًا من الدروس المكتملة محليًا، ومؤشرات لكل مادة ومهام اليوم. أضيفت لوحة أوامر/بحث سريع للأدوار الأخرى عبر `Ctrl/Cmd+K`.

لوحة المدرس تقرأ أعداد الدروس والفيديوهات والامتحانات والواجبات وقائمة المحتوى الحديث ضمن حدود Firestore Lite (حتى 20 سجلًا؛ `20+` يعني وجود المزيد). عدد الطلاب يعرض «غير متاح» وفق الصلاحيات الحالية بدل استنتاجه. لوحة المدير تميز ملفات `users` وأدوارها المخزنة عن حسابات Firebase Authentication. بوابة ولي الأمر توفر مواقع للأداء والحضور والاختبارات والجدول، وتبقى برسائل حالة صريحة حتى ربط حساب الطالب؛ لا توجد رسوم أو نتائج افتراضية.


### حالة التحقق لهذه الحزمة

نجح `npm run check` و`npm run build` بعد آخر التعديلات. لم يتوفر Firebase CLI/محاكي قواعد محلي في بيئة المهمة؛ لم تُشغّل اختبارات تكامل للقواعد ولم تُنشر إلى مشروع حي. يلزم إتمام هذه الخطوة في بيئة staging قبل إطلاق المنصة للمدرسة.
